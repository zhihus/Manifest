# Манифест проекта

## 1. Манифест

Определяет структуру ключевых файлов проекта, правила взаимодействия модели с ними, ограничения на создание и редактирование файлов, принципы автоматизации и контроля процессов.

**Основной принцип наполнения файлов:** минимальный объём информации при максимальной понятности для LLM. Приоритет — минимизация расхода токенов контекста. Модель читает только необходимые для текущей задачи файлы, использует перекрёстные ссылки для навигации, избегает дублирования и повторного чтения неизменившихся данных.

### Процессы, контролируемые манифестом

1. Структура проекта и навигация.
2. Правила разработки.
3. Версионирование.
4. Логирование.
5. Тестирование и контроль качества.
6. Проверка документации.
7. Сборка.
8. Коммиты.
9. Контроль целостности проекта.
10. Релизы.
11. Управление изменениями.
12. Безопасность.
13. Автоматизация.
14. Завершение задачи.

## 2. Модель

Анализирует проект, создаёт и изменяет код, документацию и инструкции в установленных границах, поддерживает перекрёстные ссылки по заданным шаблонам.

## 3. Скрипты

Выполняют формализуемые операции: версионирование, проверки, сборку, тестирование и подготовку коммитов.

## 4. Пользователь

Определяет принципы и ограничения, утверждает решения, требующие его участия.

---

**Главный принцип разделения ответственности:** модель анализирует и создаёт данные, скрипты выполняют однозначные операции, манифест регулирует взаимодействие, пользователь определяет правила.
