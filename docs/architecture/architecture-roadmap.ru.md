# Architecture Roadmap — Manifest

**Версия:** 1.1.0  
**Статус:** рабочая редакция  
**Назначение:** разделить объём MVP и последующие этапы развития Manifest; зафиксировать предусловия MVP и нерешённые технические вопросы. Источники: `architecture-brief.ru.md` v0.4.0 (§12, §13), `architecture-decisions.ru.md` (§11, §12), протокол 22.11.2026 (`architecture-session-2026-11-22.ru.md`), `workflow/roadmap.en.md` v1.1.0. Новых решений документ не вводит.

## 1. MVP

### 1.1. Входит в MVP

1. Manifest Core (архитектура, стандарты, правила, конфигурация, шаблоны).
2. Структура и набор утверждённых шаблонов (для MVP — один общий
   шаблон, решено 22.11.2026).
3. `manifest-init` (анализ, интервью, конфигурация, Preflight, установка).
4. Конфигурация типов и направлений проектов (Code / Documentation / Mixed).
5. Preflight (без автоисправления — диагностика и понятный отчёт).
6. Установка контекстных файлов с защитой от перезаписи.
7. Установка Git Hooks и контрольных скриптов.
8. Интеграция процессов Todoing и OpenSpec, включая отмену задач:
   любой агент рекомендует отмену с обоснованием, отмену подтверждает
   только пользователь, оркестратор меняет статус в Todoing и
   архивирует OpenSpec change штатным механизмом Archive без
   обновления основных спецификаций (решено 22.11.2026).
9. Контроль согласованности Todoing ↔ OpenSpec ↔ Git.
10. Подключение `context-files-guard`.
11. Поддержка новых и существующих Git-проектов с отсутствующим или частичным набором контекстных файлов.

Архивирование отключённых шаблонов: функция согласована, **включение в MVP не решено** — требует решения пользователя (`architecture-decisions.ru.md` §11).

### 1.2. Предусловие MVP

Минимальный контракт Todoing (статус решения — ПП): поля связей с OpenSpec/Git, версия контракта, история, версии задач, эксклюзивные блокировки.

### 1.3. Не входит в MVP (зафиксировано)

- Автоматическое объединение существующих контекстных файлов с шаблонами.
- Полная миграция проектов с собственной развитой системой контекста.
- Автоматическое обновление шаблонов во всех ранее подключённых проектах.
- Автоматическое исправление проблем, обнаруженных Preflight.
- GUI Todoing и общий обзор задач.
- Реализация экспорта/импорта и резервирования (контракт согласован, реализация отложена).
- Удалённое хранилище резервных копий.

При этом возможность дальнейшего развития учитывается в архитектуре.

## 2. Roadmap (после MVP)

Пункты roadmap не влияют на объём MVP и выполняются после его фиксации:

1. Архивирование шаблонов (если пользователь решит вынести его из MVP).
2. Специализированные шаблоны для разных типов проектов
   (решено 22.11.2026).
3. Утверждаемый процесс обновления файлов Manifest в подключённых
   проектах; обновление не является повторной инициализацией, детали
   процесса открыты (решено 22.11.2026).
4. Автоисправление части проблем Preflight (граница между
   автоисправлением и диагностикой — Brief §13).
5. Экспорт/импорт и резервирование Todoing.
6. Общий обзор задач между проектами, GUI Todoing.
7. Полная миграция развитых систем контекстных файлов.

Workflow-уровень (см. `workflow/roadmap.en.md` v1.1.0):

- хук `commit-msg` (валидация сообщения коммита);
- расширения парсера: обход каталога, запланированные запуски;
- правила для документационных проектов: заполнение
  `doc-content-rules.template.md`, git-workflow для doc-проектов;
- сборка дистрибуции `manifest-init` с проверкой исключений
  (без `scripts/verify.sh` и `scripts/hooks/`).

## 3. Нерешённые вопросы

Полный реестр — `architecture-decisions.ru.md` §12 и `architecture-brief.ru.md` §13. Вопросы, блокирующие MVP:

| Вопрос | Блокирует |
| --- | --- |
| Минимальный контракт Todoing | §1.2 — предусловие MVP |
| Формат конфигурационного файла и схема флагов | manifest-init (каталог `.manifest` и отдельный файл определены 22.11.2026) |
| Git-инициализация нового проекта без репозитория | manifest-init |
| Совместимость установки hooks с существующими hook-менеджерами | §1 п.7 |
| Защита контекстных файлов до записи | §1 п.6, context-files-guard |
| Синхронизация Todoing ↔ OpenSpec ↔ Git (карта статусов не требуется, решено 22.11.2026) | §1 п.9 |
| Конфликты имён существующих файлов | §1 п.6 |
| Версионирование установленных шаблонов | шаблоны, roadmap п.3 |
| Формальное определение требования 100% для кода | TEST FIRST |
| Project ID на границе интеграции | интеграция |

Неблокирующие: модель доверия; детали утверждаемого процесса
обновления Manifest-файлов; эскалация вне цикла исправлений; статус
ролей Architect/Planner; классы владения файлами при повторном
manifest-init (повторная инициализация не предусмотрена, решено
22.11.2026); журналирование контрольных операций; восстановление
архива; стратегия резервирования; роль compress-context в MVP.

## 4. Правила ведения документа

- Документ отражает только согласованные решения; при изменении решения сначала обновляются `architecture-brief.ru.md` и `architecture-decisions.ru.md`, затем этот документ.
- MVP и roadmap ведутся раздельно: перенос пункта между разделами требует решения пользователя и фиксации в реестре решений.
- Исторические материалы (аудиты, черновики решений) не удаляются.
