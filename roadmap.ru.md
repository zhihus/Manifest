# Описание
Запланированные работы для workflow проекта «Манифест». Каждый пункт —
будущий артефакт, ещё не реализованный.

## 1. Скрипт валидатора

### 1.1. Один скрипт `validate.sh` — единственный источник правды о
корректности файла. Две точки входа:

* модель запускает его проактивно после завершения работы с файлом, перед
  коммитом (основной контур);
* git pre-commit-хук вызывает тот же скрипт как страховку (хук не содержит
  своей логики, только вызов).

### 1.2. Платформа: один `sh`-скрипт. Нативно на Linux, на Windows через
Git Bash (хуки git и так исполняются в Git Bash). Без `ps1` — без
дублирования логики.

### 1.3. Проверки (управляются `Type`):

* всегда: имя файла — kebab-case, английский, суффикс языка `.en`/`.ru`;
* `Type: document`: блок метаданных (Status, Type, Version, Updated),
  раздел `# Описание`, нумерация разделов `1.` / `1.1.`,
  формат `Version` `X.Y.Z`, формат `Updated` `YYYY-MM-DD`.

### 1.4. Результат: `exit 0` — ок; `exit 1` + конкретное сообщение в stderr
(например, «файл X: отсутствует поле `Type`»), которое модель читает и
исправляет.

### 1.5. Открытый вопрос: где зафиксировать обязанность модели запускать
валидатор после работы — в `AGENTS.md` (правило проекта) или в
`file-structure-rules` (часть структуры процесса).
