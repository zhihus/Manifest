# Правила именования файлов

> **Status: draft**

Универсальные правила именования файлов любого проекта, подключённого к
фреймворку «Манифест».

## 1. Правила

* **kebab-case, нижний регистр, без пробелов**: `file-naming-rules.md`,
  а не `File Naming Rules.md` или `fileNamingRules.md`.
* Имена на **английском**; сокращения допустимы, если они однозначны.
* Слова разделяются дефисами; точки используются только для расширения.
* Даты в имени — только если файл неизменяемый снапшот; тогда `YYYY-MM-DD`
  идёт **последним** суффиксом: `report-name-2026-11-07.md`.
* Номера версий в имени — не для версионируемого контента (историю несёт
  git). Суффикс версии допустим только для выпущенных неизменяемых
  артефактов: `report-name-1.0.0.md`.
* Один логический документ в одном файле; не встраивайте порядковые номера
  (`report-2.md`) — имя отражает содержание, а не порядок создания.

## 2. Языковые суффиксы

* По умолчанию (без суффикса) — английский оригинал: `README.md`.
* Когда существуют обе языковые версии, английский файл несёт `.en`:
  `README.en.md` + `README.ru.md`.
* Файл `.en.md` авторитетен; файлы `.ru.md` — копии для пользователя и
  исключены из контекста агентов паттерном `*.ru.md` в `.llmignore`.

## 3. Соглашения по директориям

* `docs/plans/`: `plan-<тема>[-stage-N].en.md` (+ пара `.ru.md`).
* `openspec/changes/<имя-изменения>/`: имена артефактов зафиксированы
  пайплайном OpenSpec — `proposal.md`, `design.md`, `tasks.md`,
  `verify.md` (никогда не локализуются и не переименовываются).
* Спеки: `openspec/specs/<capability>/spec.md`.
* Тестовые/прогонные артефакты: `test-run-reports/` — `<что>-<версия>.md`
  (например, `reviewer-summary-report-1.0.0.md`).

## 4. Код и скрипты

* Скрипты и исходники следуют доминирующему соглашению языка того проекта,
  в котором живут; в doc-only проектах shell-скрипты используют
  kebab-case: `check-compression.sh`.
* Временные файлы живут только в `temp/` (в gitignore) и никогда не
  именуются так, как если бы были артефактами проекта.

## 5. Статусная строка документа (требования, продиктованы дословно)

> Требования ниже продиктованы пользователем. Они временно размещены здесь
> до появления отдельного файла по структуре документов в `workflow/`;
> этот файл станет владельцем раздела, и раздел надо перенести туда
> дословно.

* Каждый Markdown-файл имеет структуру. Минимум: заголовок — начинается
  с `#` — и статусная строка.
* Статусная строка — ровно одно слово: `**Status: draft**`. Больше ничего
  в неё не добавляется.
* Фиксированный набор статусов (три базовых):
  * `draft` — в разработке;
  * `approved` — утверждён;
  * `archived` — архив.
* Разделы и подразделы нумеруются иерархически, через точку, по глубине:
  `1.` → `1.1.`, `1.2.` → `1.2.1.` (каждый уровень добавляет один
  компонент).
