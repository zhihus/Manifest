# Описание
Запланированные работы для workflow проекта «Манифест». Каждый пункт —
будущий артефакт, ещё не реализованный.

## 1. Процесс верификации

### 1.1. Коммит

Модель обязана коммитить — требование зафиксировано в файлах контекста
(в каких — решим позже).

### 1.2. Верификация

Модель обязана запускать скрипт верификации перед коммитом —
требование зафиксировано в файлах контекста (в каких — решим позже).

### 1.3. Скрипт

Универсальный формат; все машинно проверяемые проверки:

* наличие реквизитов, заголовков, нумерации разделов, форматов
  `Version` / `Updated`;
* состав (содержимое) НЕ проверяется — меняется от проекта к проекту;
* версия и дата проверяются по git-дельте (staged vs HEAD): содержимое
  изменилось → `Updated` обязан отличаться; `approved` → `Version`
  обязан отличаться; `draft` → версия не проверяется;
* `Type` — гейтер, выбирающий набор проверок.

### 1.4. Второй хук — `commit-msg`

Проверяет сообщение коммита по `commit-rules.md`.

### 1.5. Открытые вопросы

* формат рендера блока метаданных (таблица / `<br>` / отдельные
  блок-цитаты);
* где зафиксировать обязанности модели (коммит, верификация) — в
  `AGENTS.md` или в файлах правил.

### 1.6. Сборка дистрибутива — исключения

В `dist/` манифест-init не входят `scripts/verify.sh` и
`scripts/hooks/` Манифеста: это dev-инфраструктура самого проекта, а
не фреймворка. Будущий change на наполнение `dist/` обязан включить
сценарий-приёмки: `dist/` не содержит этих файлов.

### 1.7. Расширения скрипта

Точки расширения парсера структуры вне MVP (MVP принимает один файл):

* обход директории — проверка всех файлов, а не одного;
* запуск по расписанию.

## 2. Doc-проекты

### 2.1. Шаблон правил для doc-проектов

`doc-content-rules.template.md` — шаблон правил для **документационных**
проектов (проекты, создающие документацию, а не код). Содержание:

* правила для документационных проектов (аналог
  `code-rules.template.md`, но для документации): Clarity, Accuracy,
  Completeness, Consistency, Structure, Change Discipline, Verification;
* временный блок защиты контекст-файлов: при изменении
  agent/rules-файлов — показать изменения + ревью + явное согласие
  пользователя перед коммитом (пока не существует Git Hook);
* git-воркфлоу — нерешён (см. 2.2).

Статус: **не реализовано** — в
`docs/templates/doc-content-rules.template.md` шаблон-заглушка
`{{PENDING}}`; считается готовым только когда завершены все пункты,
включая git-воркфлоу.
