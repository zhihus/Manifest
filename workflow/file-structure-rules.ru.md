## 1. Блок метаданных

* Блок метаданных расположен в шапке документа, под заголовком. Это группа
  строк-стрелок:
  * `> **Status: draft**`
  * `> **Type: document**`
  * `> **Version: 1.0.0**`
  * `> **Updated: 2026-11-07**`
* Статусная строка — ровно одно слово: `**Status: draft**`. Больше ничего
  в неё не добавляется.
* Набор статусов (три базовых, расширяемый):
  * `draft` — в разработке;
  * `approved` — утверждён;
  * `archived` — архив.
* `Version` — трёхкомпонентное число `X.Y.Z`.
* `Updated` — дата последнего изменения, ISO `YYYY-MM-DD`.
* `Status` — первичное поле. Версионирование зависит от статуса и от
  структуры. Список статусов определён здесь и расширяемый.

Примечание: документ структуры (этот файл) определяет список статусов и
расположение блока метаданных. Документ изменения метаданных определяет,
как меняется каждое поле метаданных. Статусы и версии описываются здесь,
а не в правилах версионирования.

## 2. Тип

* `Type` определяет набор правил, применяемых к файлу.
* Типов несколько; известное значение — `document`. Набор расширяемый.
* `document` — Markdown-документ, подчинённый полной структуре документа
  (блок метаданных, раздел «Описание», нумерация разделов, версионирование,
  суффикс языка).

## 3. Нумерация разделов

* Разделы и подразделы нумеруются иерархически, через точку, по глубине:
  `1.` → `1.1.`, `1.2.` → `1.2.1.` (каждый уровень добавляет один компонент).

## 4. Подразделы с метками

* Если раздел содержит несколько частей с метками (например, правильно /
  неправильно), метки — отдельные строки текста под одним заголовком
  раздела, а не отдельные подзаголовки с меткой в тексте заголовка.

  Правильно:

  ```
  ### 2.1. Файлы

  Правильно

  ✅ `naming-rules.en.md`
  ✅ `naming-rules.ru.md`

  Неправильно

  ❌ `File Naming Rules.en.md`
  ❌ `fileNamingRules.en.md`
  ```

  Неправильно:

  ```
  ### 2.1. Файлы — правильно

  ✅ `naming-rules.en.md`
  ✅ `naming-rules.ru.md`

  ### 2.2. Файлы — неправильно

  ❌ `File Naming Rules.en.md`
  ❌ `fileNamingRules.en.md`
  ```
