# Description
Однопроходное подключение Manifest/OpenSpec/Todoing к агенту потребительского проекта.

## Выполнение одним запуском

1. **Аудит.** Зафиксировать корень, branch, HEAD и Git status. Прочитать
   AGENTS.md, навигацию, .llmignore и правила публикации. Проверить
   .manifest/manifest.yaml, checksum, format_version, switches, OpenSpec,
   Todoing, Project ID, config и store. Существующую БД только читать/проверять.

2. **Режим.** Сопоставить switches с поручением пользователя. Для совместной
   работы нужны включённые OpenSpec и Todoing. Менять только разрешённые
   switches по фактической схеме Manifest; checksum пересчитать штатно.
   Неизвестная схема, повреждённый store, сомнительный binary provenance или
   конфликт правил — остановка с отчётом.

3. **Контекст агента.** На основе
   `workflow/connected-agent-onboarding.ru.md` создать краткую локальную
   инструкцию, применимую к проекту. Сохранить правила создания спецификаций,
   связь change/task, полномочия, lifecycle и ссылки на нормативные контракты.
   Не копировать ненужные внутренности Manifest и не включать клиентские данные,
   локальные пути или секреты.

4. **Точки входа.** Добавить ссылку на инструкцию в AGENTS.md и навигационную
   карту проекта. Проверить доступность через .llmignore. Существующие правила
   не заменять целиком.

5. **Готовность.** Убедиться, что агент при старте понимает switches и режим,
   критерии создания change/task, правило одна change = одна task только в
   coordinated mode, хранение FR в tasks.md, полномочия, переход
   backlog → ready, Review и recovery. Использовать read-only проверки:
   задачи, changes, тестовые записи и коммиты не создавать.

## Ограничения

Не менять бизнес-логику и пользовательские данные; не пересоздавать Todoing
store; сохранять незакоммиченные файлы и историю; не публиковать локальные
конфиги/БД/клиентские материалы. Не выполнять commit, push, PR, merge;
не удалять ветки/worktree и не менять ядро Manifest. При конфликте с правилами
публикации остановиться и запросить решение пользователя.

## Готовность и отчёт

Готово, если конфигурация и checksum валидны, включённые компоненты доступны,
агент обнаруживает обязательную инструкцию, правила OpenSpec ↔ Todoing
согласованы с контрактами, пользовательские данные сохранены и ничего
не создано/не опубликовано.

Отчёт: изменённые файлы, switches до/после, проверки, ограничения;
подтвердить отсутствие новых tasks/changes, коммитов и remote-изменений.
