# Правила изменения метаданных файла

# Метаданные
> **Status: approved**
> **Type: document**
> **Version: 1.0.0**
> **Updated: 2026-11-07**

# Описание
Правила изменения блока метаданных файла-документа проекта,
подключённого к фреймворку «Манифест».

## 1. Версия

### 1.1. Формат версии

#### 1.1.1. Версия

Трёхкомпонентное число: `X.Y.Z`.

### 1.2. Повышение версии

#### 1.2.1. X (major)

Ломающие изменения: существующее содержание удалено или изменено по смыслу.

#### 1.2.2. Y (minor)

Добавлено новое содержание, существующее расширено.

#### 1.2.3. Z (patch)

Уточнения, исправления формулировок, опечатки.

### 1.3. Зависимость от статуса

#### 1.3.1. Новый документ в статусе `draft` получает версию `1.0.0`.

#### 1.3.2. Версия изменяется ТОЛЬКО для документа в статусе `approved`.

#### 1.3.3. Изменение статуса `draft` → `approved` или `approved` → `archived` не меняет версию.

## 2. Дата

### 2.1. Дата `> **Updated: YYYY-MM-DD**` — дата последнего изменения.

### 2.2. Дата обновляется при каждом изменении.

## 3. Тип

### 3.1. Тип файла: `> **Type: document**`.

### 3.2. Правила изменения типа не предусмотрены.

## 4. Статус

### 4.1. Статус документа изменяется по требованию пользователя.

### 4.2. Автоматическое изменение статуса не предусмотрено.

### 4.3. Изменение статуса агентом

Статус документа может изменяться агентом в определённых процессах манифеста;
список этих процессов не определён.

### 4.4. Статусная строка

Статусная строка — ровно одно слово: `**Status: draft**`.
Больше ничего в неё не добавляется.

## 5. Примеры

### 5.1. Правильный

Правильный блок метаданных — в шапке этого документа.

### 5.2. Неправильные

❌ Статус с лишним текстом: `> **Status: draft**` (в разработке)

❌ Статус со значением вне списка: `> **Status: in-development**`

❌ Версия не по формату: `> **Version: 1.0**`

❌ Дата не по формату: `> **Updated: 07.11.2026**`
